# Хмель — учёт и касса пивного магазина

Веб-приложение с базой данных PostgreSQL: учёт товаров по штрихкодам и категориям,
касса со сканером и поиском, история чеков с корзиной, фото товаров, роли администратора и кассира.

## Роли доступа

- **Администратор** — товары (добавление, редактирование, удаление, цены, остатки, штрихкоды,
  фото, управление категориями), полная история чеков всех кассиров, корзина удалённых чеков,
  управление пользователями.
- **Кассир** — касса (сканирует и продаёт товар), может **добавлять** новые товары,
  но не может их редактировать или удалять, видит историю **своих** чеков.
  Ограничения проверяются на сервере, а не только скрыты в интерфейсе.

## Штрихкод-сканер

Обычный USB- или Bluetooth-сканер работает как клавиатура: он «печатает» цифры штрихкода
и в конце сам нажимает Enter. На экране кассы есть поле «Наведите сканер…», которое всегда
в фокусе — просто сканируйте товар, он найдётся по штрихкоду и добавится в чек.
Также можно вбить код вручную и нажать Enter, либо выбрать товар кликом или через поиск/категории.

## Установка

### 1. База данных

Проще всего поднять PostgreSQL через Docker:

```bash
docker compose up -d
```

Либо используйте уже имеющийся у вас сервер PostgreSQL — тогда просто создайте
базу данных и пользователя самостоятельно (через pgAdmin или psql).

### 2. Настройка окружения

```bash
cp .env.example .env
```

Откройте `.env` и укажите:
- `DATABASE_URL` — строку подключения к вашей базе,
- `JWT_SECRET` — любую длинную случайную строку (используется для подписи токенов входа).

### 3. Установка зависимостей и применение схемы

```bash
npm install
npm run migrate
```

Команда `migrate` создаст таблицы и, если пользователей ещё нет, загрузит демо-данные:
- админ: `admin` / `admin123`
- кассир: `kassir` / `kassir123`
- 6 примеров товаров со штрихкодами и категориями

**Обязательно смените демо-пароли** в разделе «Пользователи» после первого входа.

### 4. Запуск

```bash
npm start
```

Приложение будет доступно на `http://localhost:3000` (или на порту из `.env`).

## Структура проекта

```
server/            Express API (аутентификация, товары, категории, чеки, пользователи)
  routes/
  middleware/
db/
  schema.sql        Структура таблиц
  seed.sql          Демо-данные (пароли уже захешированы)
  migrate.js        Скрипт применения schema.sql/seed.sql
public/             Фронтенд (обычный HTML/CSS/JS, без сборки)
  uploads/products/ Загруженные фото товаров
docker-compose.yml  PostgreSQL для локальной разработки
```

## Как это защищено

- Пароли хранятся в базе в виде bcrypt-хешей, а не открытым текстом.
- Вход выдаёт JWT-токен на 12 часов; все запросы к API проверяют его подлинность.
- Изменение/удаление товаров, фото, категорий и пользователей возможно **только** с ролью
  `admin` — проверка происходит в middleware на сервере, так что кассир не сможет обойти
  это через браузер. Кассиру доступно только создание новых товаров.
- Списание остатков при продаже происходит в транзакции БД, поэтому продать больше,
  чем есть на складе, невозможно даже при одновременной работе нескольких касс.
- Удаление чека перемещает его в корзину (мягкое удаление); полное стирание — отдельное
  явное действие администратора.

## Продакшн-развёртывание

Для реальной работы (не только локально) потребуется:
1. Развернуть PostgreSQL и сам Node.js-процесс на сервере или в облаке (например, Render, Railway, VPS).
2. Настроить HTTPS (через reverse-proxy вроде Nginx или встроенные средства хостинга).
3. Задать надёжный `JWT_SECRET` и ограничить доступ к базе данных.
4. Настроить регулярное резервное копирование базы данных и папки `public/uploads`.

Готов помочь с любым из этих шагов, если понадобится.
